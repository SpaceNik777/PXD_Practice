# РХД — практические работы: PostgreSQL + Go

Учебные работы по дисциплине «РХД» на сквозном проекте **TeamBoard** (арендаторы → проекты → задачи). Стек: Go 1.26.8, PostgreSQL 17.10 (`postgres:17.10-alpine`, Docker Compose с healthcheck и томом), драйвер `pgx/v5` (модуль `example.com/teamboard`). Все работы — вариант A (номер в группе 16, чётный).

## Состав работ

| Работа | Тема | Порт стенда | Ключевое |
|---|---|---|---|
| РХД-1 | «Нагрузка, инварианты и целевые показатели качества хранилища», вариант A «Преимущественно чтение: лента проекта» | 55432 | схема и детерминированный сид (001/002/002b, инвариант составным FK), генератор нагрузки `cmd/load` (workers/pool/requests/timeout, распределение 80/20), паспорт нагрузки `evidence/01-workload.md` |
| РХД-2 | «Многоарендность и защита на уровне строк (RLS)», вариант A | 55433 | миграции 003/003b: роль `teamboard_app`, схема `app`, `app.current_tenant_id()`, RLS ENABLE+FORCE, `project_members` с составным FK; обёртка `internal/tenantdb` (`WithTenantTx`), интеграционные тесты изоляции |
| РХД-3 | «Конкурентные транзакции и идемпотентные команды», вариант A «Оптимистическая блокировка» | 55434 | миграция `004_idempotency.sql` (таблица `command_requests`), демон перекоса записи, SERIALIZABLE + retry (`internal/command`), оптимистическая блокировка по `version`, идемпотентные команды |

Каждая папка — самостоятельный compose-проект (`a`, `rhd2`, `rhd3`), не пересекающийся по контейнерам, томам и сетям.

## Структура репозитория

```
├── РХД-1/Вариант-A/   # compose.yaml, migrations/, cmd/load/, evidence/
├── РХД-2/Вариант-A/   # + internal/tenantdb/, миграции RLS, check-скрипты
├── РХД-3/Вариант-A/   # + internal/command/, миграция 004, demo-сценарии перекоса записи
└── Отчёты/            # РХД-01.md, РХД-02.md, РХД-03.md
```

`evidence/` — паспорта нагрузок, модели угроз и протоколы экспериментов (включая SQL-сценарии демонстрации перекоса записи и идемпотентности) — это фактические результаты, на которых построены отчёты.

## Порты

Порт 5432 на хосте занят посторонним сервисом, поэтому стенды проброшены на `55432` (РХД-1), `55433` (РХД-2), `55434` (РХД-3); порт внутри контейнера не менялся (5432).

## Запуск (команды из отчётов)

Поднять стенд и применить миграции одной транзакцией (порядок и полный протокол — в отчёте соответствующей работы):

```
cd "РХД-1/Вариант-A"
docker compose up -d --wait
```

Миграции применяются от пользователя `postgres` через `psql -X -1 -f - -v ON_ERROR_STOP=1` (точные команды — в отчётах).

Генератор нагрузки РХД-1 (переменная окружения `DATABASE_URL`):

```
DATABASE_URL=postgres://postgres:postgres@localhost:55432/teamboard?sslmode=disable
go run ./cmd/load -workers 8 -requests 500
```

Тесты РХД-2/РХД-3 ходят в базу от роли приложения `teamboard_app` (создаётся миграцией 003):

```
# РХД-2 (порт 55433):
APP_DATABASE_URL=postgres://teamboard_app:teamboard_app@localhost:55433/teamboard?sslmode=disable
go test -race ./... -count=1

# РХД-3 (порт 55434):
APP_DATABASE_URL=postgres://teamboard_app:teamboard_app@localhost:55434/teamboard?sslmode=disable
go test -race ./... -count=1
```

Проверки качества: `gofmt -l .`, `go vet ./...`, `go test -race` (CGO_ENABLED=1).
